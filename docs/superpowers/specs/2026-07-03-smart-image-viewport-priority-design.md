# SmartImage 视口优先加载设计

## 背景

`SmartImage` 当前使用 `IntersectionObserver` 延迟提交图片任务，再由全局调度器限制并发并按静态优先级排序。但组件在首次进入预加载区后立即断开观察器，快速滚动离开时无法取消任务；相同优先级任务又保持入队顺序，因此目标视口中的图片可能长期排在已滑过图片之后。

本次目标是让尚未开始的图片任务由当前视口状态驱动，而不是单纯按照入队顺序执行。已经设置 `img.src` 的请求不强制中断，避免重复请求、闪烁和浏览器差异。

## 方案

采用“双层观察器 + 可更新优先级任务”：

- 预加载区观察器使用组件现有 `rootMargin`，决定图片是否应延迟入队。
- 真实视口观察器固定使用 `0px` 边界，决定排队任务是否应提升为视口优先级。
- 调度器允许尚未执行的任务更新优先级；已执行任务继续自然完成。
- 快速滑出预加载区时，取消延迟计时器和未执行任务。

该方案比只修复观察器更能保证当前视口优先，也避免按滚动距离持续测量 DOM 所带来的额外开销。

## 组件职责

### `SmartImage.vue`

组件继续负责单张图片的候选地址、加载状态、错误回退和展示效果，并新增以下可见性状态：

- `inPreloadZone`：元素位于带 `rootMargin` 的预加载区域。
- `inViewport`：元素与真实视口相交。

行为规则：

1. `eager=true` 时跳过两个观察器，立即按传入的 `priority` 调度。
2. 首次进入预加载区但未进入真实视口时，保留 `loadDelay`，到期后按普通传入优先级入队。
3. 进入真实视口时，取消延迟并立即入队；若任务已排队，则提升为视口优先级。
4. 离开真实视口但仍在预加载区时，尚未执行的任务降回传入优先级。
5. 离开预加载区时，取消延迟和尚未执行的任务。
6. 已执行任务不因可见性变化而重复调度或中断。
7. `src` 变化和组件卸载时，断开两个观察器并清理所有任务状态。

视口优先级通过独立常量计算，保证它严格高于普通队列任务，同时保留调用方传入优先级之间的相对顺序。

### `imageLoadScheduler.js`

`scheduleImageTask` 返回任务句柄：

```js
{
  cancel(),
  updatePriority(priority),
}
```

任务具有 `queued`、`running`、`settled` 三种内部阶段：

- `cancel()` 只阻止 `queued` 任务执行；`running` 任务继续完成。
- `updatePriority()` 只修改 `queued` 任务并重新整理队列。
- `release()` 只能结算一次，防止重复回调导致并发计数失真。

现有内部调用方 `SmartImage`、`v-lazy` 指令和 `preloadImageUrl` 同步迁移到任务句柄接口。对外的 `preloadImageUrl` 返回结构仍保持 `{ promise, cancel }`。

## 数据流

1. 图片进入预加载区，组件启动稳定性延迟。
2. 延迟结束仍在预加载区，则任务进入全局队列。
3. 图片进入真实视口，组件调用 `updatePriority()`；若尚未入队则立即创建视口优先任务。
4. 调度器每次入队、更新优先级或释放并发槽时重新选取优先级最高的任务。
5. 图片加载成功或失败后调用 `release()`，组件沿用现有成功、候选地址回退及失败展示流程。

## 兼容与降级

- 保留 `src`、`alt`、`eager`、`priority`、`skeleton`、`progressive`、`rootMargin` 和 `loadDelay` 的现有语义。
- 不改变 `load`、`error` 事件载荷。
- 不改变图片候选地址和备用域名逻辑。
- 不支持 `IntersectionObserver` 的环境直接调度加载，避免图片永久停留在骨架状态。
- 调度器仍保留网络状况自适应并发上限。

## 测试

调度器单元测试覆盖：

- 高优先级任务先于较早入队的低优先级任务执行。
- 排队任务更新优先级后能够提前执行。
- 取消排队任务后不会执行。
- 更新或取消运行中任务不会重复执行或破坏并发计数。
- `release()` 重复调用不会使活动任务数变为负数。

组件测试使用可控的 `IntersectionObserver` 模拟器覆盖：

- 快速经过预加载区并离开时不会提交请求。
- 真实视口图片能够超过先入队的预加载图片。
- 离开真实视口后，排队任务恢复普通优先级。
- 已经开始的请求在离开视口后继续完成，且不会重复设置 `src`。
- `src` 更新及卸载会清理观察器、延迟和排队任务。
- 缺少 `IntersectionObserver` 时能够直接加载。

## 非目标

- 不强制终止已经发起的浏览器图片请求。
- 不按像素距离持续计算每张图片的动态排名。
- 不在本次改造中合并 `SmartImage` 与旧 `v-lazy` 指令的两套可见性逻辑。
