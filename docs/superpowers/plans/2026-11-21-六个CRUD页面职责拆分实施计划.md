## 2. 各层契约

| 位置 | 状态及行为 | 对外契约 |
| --- | --- | --- |
| 路由页面 | 当前编辑对象、弹窗 visible、组件连接 | 编辑事件打开弹窗；saved 触发列表刷新 |
| 业务列表 composable | 原始列表、查询、filteredData、loading、error、刷新、删除；餐厅包含批量删除，租户包含状态流转 | 返回列表实际使用的状态与命名明确的操作 |
| 业务 FormDialog | 独立草稿、isEdit、校验规则、选项、saving、保存失败反馈 | `visible` 双向绑定、具体业务对象 prop、`saved` 事件 |
| 纯 form 模块 | 草稿类型、默认值、回填、创建与更新载荷 | 不请求接口，不拥有响应式状态，不调用通知 |
| 角色权限编辑 | 菜单数据、勾选草稿、权限合并、保存及现有面板进出时序 | 独立 `useRolePermissions`，权限面板使用它，页面监听 saved |
| 租户日志弹窗 | 所选租户的日志、加载和错误 | 接收 tenant 和 visible，自己调用日志接口 |

表单函数使用具体业务类型：`createRoleForm`、`createTenantForm`、`createFoodForm`、`createMenuForm`、`createDeptForm`、`createRestaurantForm`。保存转换采用对应的 `toCreateXxxParams`/`toUpdateXxxParams`；创建和更新请求形状一致时可以共用业务专属的 `toXxxPayload`，无需凑出两个重复函数。

身份来自编辑对象，不再把 `_tenantId` 或判断编辑模式的 ID 塞进草稿。现有请求若包含 ID 字段，则在转换时从编辑对象明确传入，保持接口载荷。复制数组，编辑或取消不能改到列表原对象。

菜单、部门额外接收原始树和 `initialParentId: number | null`。从行的新增子级事件打开新增编辑器时设置初始父级；从顶部新增时设为 null；编辑时以原对象 parentId 为准。父级选项维持当前排除自身的规则，保留筛选祖先，不借本次重构新增后代排除规则。

## 3. 公共的错误与时序要求

- 每次列表刷新使用递增版本；旧请求和作用域销毁后的响应不回写列表、错误或 loading。
- 列表加载失败写入 error；再次刷新清空旧错误。删除失败保留列表并沿用共享 HTTP 反馈，取消确认不调用删除接口。
- 编辑器打开时创建独立草稿并清理校验；取消后再次打开恢复默认或当前对象，不保留前一会话草稿。
- 选项加载失败给出可见反馈与重试；必要选项未就绪时禁用保存，允许取消。关闭或切换对象后丢弃旧选项结果。
- 公共弹窗继续拥有表单校验和防重复提交；saving 期间阻止修改草稿和关闭。
- 保存失败保留草稿并允许重试。保存成功关闭并 emit saved，刷新失败只显示列表错误，不显示保存失败。
- 只对本轮改动文件补充必要的 WHY 注释；涉及框架机制的说明必须先有安装源码或官方文档证据。
